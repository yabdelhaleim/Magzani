# اختبار واجهة الإشعارات — Magzani

> هذه القائمة تختبر ما يظهر للمستخدم من المتصفح. تُنفذ على بيئة staging ببيانات تجريبية وحسابي `admin` و`employee`.

## مسؤولية كل نوع من الرسائل

| السطح | ما يعرضه | مدة الظهور |
|---|---|---|
| Toast أعلى الصفحة | نتيجة العملية الحالية: نجاح، خطأ، تحذير أو معلومة | النجاح والمعلومة 5 ثوانٍ؛ الخطأ والتحذير حتى الإغلاق |
| جرس الإشعارات | أمور مهمة تحتاج متابعة: إلغاء فاتورة، مرتجع، مخزون منخفض، فاتورة متأخرة، إشعار نظام | محفوظ حتى القراءة |
| تنبيهات POS / Livewire / AJAX | تحقق أو نتيجة مرتبطة بالشاشة المفتوحة فقط | محلية حسب الشاشة |
| تحذير فشل الترحيل | مشكلة محاسبية غير محلولة | لوحة التحكم الرئيسية للمصرح لهم فقط |
| تنبيهات المخزون في Dashboard | ملخص حي لحالة المخزون وليس Inbox | طالما المخزون تحت الحد |

لا يجب أن تدخل عمليات «تم إنشاء فاتورة»، «تم تسجيل دفعة» أو «اكتمل تحويل فوري» إلى عداد الجرس؛ يكفي Toast العملية.

## تجهيز الاختبار

- [ ] `APP_DEBUG=false` حتى لا تظهر تفاصيل تقنية للمستخدم.
- [ ] migrations الخاصة بالـ tenant محدثة، ومنها جدول `notifications`.
- [ ] حساب admin نشط وحساب employee نشط.
- [ ] مخزن ومنتج بحد أدنى معروف، وفواتير قابلة للإلغاء والإرجاع.
- [ ] فتح DevTools ومراقبة Console وNetwork طوال الاختبار.

## A. الحالة الأساسية للجرس

1. امسح/علّم إشعارات الحساب التجريبي كمقروءة.
2. افتح Dashboard ثم أي صفحة أخرى.

**المتوقع:**

- [ ] لا توجد نقطة أو badge حمراء عندما العدد صفر.
- [ ] فتح الجرس يعرض «لا توجد إشعارات مهمة».
- [ ] لا يوجد خطأ JavaScript أو request فاشل.
- [ ] زر الجرس يعمل بالنقر وEnter/Space وله focus واضح.

## B. إلغاء فاتورة مبيعات

1. افتح فاتورة قابلة للإلغاء ونفذ الإلغاء.
2. راقب Toast ثم الجرس.
3. افتح إشعار الإلغاء.

**المتوقع:**

- [ ] Toast نجاح واحدة فقط، وليست نسختين في الصفحة.
- [ ] badge يزيد بمقدار واحد.
- [ ] الإشعار Warning ويحمل رقم الفاتورة.
- [ ] فتحه يذهب إلى تفاصيل الفاتورة ويعلّمه مقروءاً.
- [ ] بعد refresh يبقى مقروءاً وينخفض العداد.

## C. مرتجعات المبيعات والمشتريات

نفّذ مرتجعاً صحيحاً من كل نوع.

- [ ] إشعار واحد لكل مرتجع، بلا تكرار.
- [ ] الاسم/الرقم/المبلغ صحيح.
- [ ] رابط مرتجع المبيعات يفتح `invoices.sales-returns.show`.
- [ ] رابط مرتجع المشتريات يفتح `invoices.purchase-returns.show`.
- [ ] rollback أو validation failure لا ينشئ notification.

## D. المخزون المنخفض

1. اضبط مخزون منتج فوق الحد الأدنى.
2. نفذ حركة تجعله يساوي الحد أو ينخفض تحته.
3. نفذ حركة ثانية وهو ما زال منخفضاً.
4. أعد المخزون فوق الحد، ثم اخفضه مرة أخرى.

- [ ] أول عبور للحد ينشئ إشعاراً واحداً.
- [ ] الحركة الثانية تحت الحد لا تكرر التنبيه.
- [ ] بعد الارتفاع فوق الحد ثم الهبوط يظهر إشعار جديد.
- [ ] `minimum_stock=0` لا يسبب division-by-zero ولا إشعاراً وهمياً.
- [ ] رابط التنبيه يفتح المنتج الصحيح.

## E. الفواتير المتأخرة

1. جهز فاتورة مؤكدة غير مدفوعة و`due_date` في الماضي.
2. شغّل `php artisan accounting:remind-overdue --days=0` في tenant التجريبي.

- [ ] يظهر إشعار بعنوان «فاتورة مبيعات متأخرة».
- [ ] عدد أيام التأخير والمتبقي صحيحان.
- [ ] رابط الفاتورة صحيح.
- [ ] لا يصل الإشعار إلى employee أو مستخدم غير نشط.

## F. عمليات لا تُحفظ في الجرس

نفّذ: إنشاء فاتورة مبيعات، إنشاء فاتورة مشتريات، تسجيل دفعة، وتحويل مخزون يكتمل فوراً.

- [ ] كل عملية تعرض Toast مناسباً مرة واحدة.
- [ ] لا يزيد عداد الجرس بسبب هذه النجاحات الروتينية.
- [ ] لا يظهر إشعار «تحويل معلّق» لتحويل أصبح `received` في نفس الطلب.

## G. القراءة والعزل

- [ ] «تعليم كمقروء» يؤثر في إشعار المستخدم الحالي فقط.
- [ ] «تعليم الكل كمقروء» يصفر عداد الأنواع المهمة فقط.
- [ ] محاولة فتح UUID يخص مستخدماً آخر ترجع 404.
- [ ] Tenant A لا يرى إشعارات Tenant B.
- [ ] refresh وback/forward لا يعيدان الإشعار إلى unread.

## H. تحذير فشل الترحيل

- [ ] يظهر على Dashboard الرئيسية للـ admin عند وجود failure غير محلول.
- [ ] لا يظهر للـ employee دون الصلاحية.
- [ ] لا يظهر على صفحات المنتجات وPOS والتحويلات.
- [ ] صفحة accounting dashboard تعرض سياقها المحاسبي مرة واحدة.
- [ ] حل المشكلة يخفي التحذير بعد تفريغ/تحديث الكاش.

## I. رسائل الصفحات المحلية

- [ ] validation يعرض أخطاء الحقول ولا ينشئ إشعار جرس.
- [ ] أخطاء/نجاح Categories AJAX تظل داخل شاشة التصنيفات.
- [ ] POS وPOS Return يعرضان تنبيهاتهما المحلية فقط.
- [ ] الخطأ والتحذير لا يختفيان تلقائياً قبل قراءتهما.
- [ ] لا تظهر SQL أو stack trace أو مسارات ملفات في Toast المستخدم.

## J. Responsive وAccessibility

اختبر بعروض 1440px، 1024px، 768px، و375px.

- [ ] القائمة لا تخرج خارج الشاشة ويمكن تمريرها.
- [ ] النص العربي لا يتداخل مع الوقت أو الأيقونة.
- [ ] badge واضح لكن لا يغطي زر الجرس.
- [ ] قارئ الشاشة يعلن عدد unread ورسائل الخطأ.
- [ ] جميع الأزرار والنماذج قابلة للتشغيل بلوحة المفاتيح.
